# /devlog — 작업 기록 + 결정 카드

너는 이 레포의 **기록 담당**이다. 코드는 한 줄도 고치지 않는다. 쓰는 파일은 아래 두 개뿐이다.

- `docs/development/dev_log.md` — 작업 기록 (무엇을 했는가)
- `docs/development/decision_log.md` — 결정 카드 (왜 그렇게 했는가, 포트폴리오 재료)

기록 범위: $ARGUMENTS
(비어 있으면 `dev_log.md`의 마지막 항목 이후 커밋 전부 + 커밋되지 않은 변경)

## 1. 사실 수집

기억이나 대화 요약이 아니라 **직접 확인한 것**만 재료로 쓴다.

1. `dev_log.md`의 마지막 항목 제목과 날짜를 읽어 기록 시작점을 정한다.
2. `git log --date=short --format='%h %ad %s'`, `git status --short`, `git diff --stat`로 범위 안의 변경을 확인한다.
3. 커밋 메시지를 믿지 말고 `git show --stat <해시>`로 실제 변경 파일을 본다. 메시지와 내용이 다르면 그 사실도 기록한다.
4. 이 세션에서 실행한 검증(테스트, 빌드, 수동 확인)과 그 결과를 정리한다. 이 세션에서 실행하지 않은 검증은 "실행했다"고 쓰지 않는다.

범위 안에 기록할 변경이 없으면 파일을 건드리지 말고 "기록할 변경 없음"이라고만 답한다.

## 2. dev_log.md에 항목 추가

파일 **맨 끝**에 추가한다. 기존 항목은 수정하지 않는다. 이전 기록이 틀렸으면 새 항목에 `**정정**:`으로 적는다.

```markdown
---

## YYYY년 M월 D일 - <작업을 한 줄로>

### 1. 목표 (무엇을·왜)
- 

### 2. 주요 변경 사항 (어떻게)
- **<영역>**: <변경 내용> (`경로/파일.py`, 커밋 `abc1234`)

### 3. 주요 결정 및 이유
- **<결정>**: <이유>  → decision_log `D-NNN`

### 4. 검증
- <실행한 명령> → <결과 수치>

### 5. 알려진 이슈 / 남은 일
- 
```

- 하루에 주제가 여러 개면 항목을 주제별로 나눈다.
- 항목 하나는 40줄을 넘기지 않는다. 길어지면 세부 내용은 관련 문서로 빼고 링크한다.

## 3. decision_log.md에 결정 카드 추가

이번 범위에서 **선택지가 둘 이상 있었던 결정**만 카드로 만든다. 단순 수정, 오타, 포맷 변경은 카드가 아니다. 보통 한 세션에 0~3장이다. 억지로 만들지 않는다.

카드 형식과 번호 규칙은 `decision_log.md` 상단의 "카드 형식"을 따른다. 번호는 파일의 마지막 `D-NNN` 다음 번호를 쓴다.

**`내 이유` 칸은 절대 채우지 않는다.** `> (작성 전)`을 그대로 둔다. 이 칸은 사용자가 직접 쓴다.

## 4. 기록 규칙

1. **근거 필수**: 변경과 결정에는 커밋 해시나 파일 경로를 붙인다. 근거를 댈 수 없는 문장은 쓰지 않는다.
2. **수치는 실측만**: 직접 실행해서 얻은 숫자만 쓴다. 측정하지 않았으면 `미측정`, 실행으로 확인하지 않았으면 `미검증`이라고 쓴다.
3. **수치 없는 평가어 금지**: "개선", "최적화", "향상", "안정화", "효율적"은 전후 수치가 같이 있을 때만 쓴다. 없으면 한 일을 그대로 적는다 (예: "N+1 쿼리를 JOIN 1회로 변경").
4. **추측 표시**: 코드나 커밋에서 확인하지 못하고 짐작한 이유에는 `(추정)`을 붙인다.
5. **한 것과 안 한 것을 구분**: 조사만 했으면 `미적용`, 보류했으면 `결정 대기`라고 쓴다.
6. **사용자 발언을 지어내지 않는다**: 사용자가 이 세션에서 말한 이유만 사용자 의견으로 적는다.
7. 기존 문체를 따른다. 한국어, 개조식, 파일·함수명은 백틱.

## 5. 문서 불일치 메모 (고치지 않고 적기만)

이번 변경이 라우트, 환경변수, 실행 명령, 의존성, DB/인증 구조를 건드렸다면 `README.md`, `CLAUDE.md`, `docs/architecture/`, `docs/guides/setup_guide.md`에서 해당 내용을 찾아 코드와 대조한다. 어긋난 곳은 `5. 알려진 이슈 / 남은 일`에 `문서 불일치: <파일>의 <내용> ↔ 코드 <경로>` 형식으로 적는다. 문서 수정은 하지 않는다.

## 6. 마무리

- `git add`, `git commit`을 하지 않는다. 커밋은 사용자가 한다.
- 마지막에 아래만 출력한다.

```
기록: dev_log.md <항목 제목> / decision_log.md <추가한 카드 번호들 또는 "없음">
미검증·미측정: <개수와 항목>
작성해 주세요: <카드 번호> 내 이유 — <그 카드에 대해 답해 볼 질문 한 줄>
```
